# creator-craft.md -- 人物/博主蒸馏专章（creator_corpus 路径）

> 适用：蒸馏对象不是「一部作品」，而是「**一个人**」的跨媒介全量语料 -- 视频博主的全部视频 + 专栏/Newsletter + 书 + 播客。
> 先例（本章程的事实来源）：Dan Koe 项目（2026-07）与 Alex Hormozi 项目（2026-08，第二人，双轨 + 桥接层由它定型）。Dan Koe：162 视频（91.9h）+ 212 Letters + 2 书 25 章 → 399 来源 / 1,836 条观点证据 / 299 观点族 → `sanshengai.top/tools/creator-distill/dan-koe`。项目档案：`Cowork\其他\Dan Koe\`（00 项目管理 / 03 工作数据 / 04 蒸馏成果 / 07 工具），交接文档：`其他\Dan Koe\网站修改交接.md`。
> 单本书 / 单视频 / 一个视频系列 → 走 SKILL.md 主管线（Step0-7），不看本文件。同一作者「已蒸 ≥2 本书」的聚合 → 走 StepA（author-craft.md）。本路径是从零蒸「一个人」。

## 0. 路由判定（进 skill 先分流）

| 蒸馏对象 | 走路径 |
|---|---|
| 一本书全文 | 主管线 Step0-B |
| 单个视频（按 1 集） | 主管线 Step0-V（单成员 series） |
| 一个视频系列 / 课程合集 | 主管线 Step0-V |
| **一个博主/人物的全部作品（跨媒介）** | **本路径（creator_corpus）** |

判断口诀：分析单位是「作品」→ 主管线；分析单位是「人」→ 本路径。用户说「蒸馏这个 UP 主 / 这个人 / 他的思想体系」即本路径。

## 1. 总原则（Dan Koe 项目定型的三句话）

**输入层全量采集，分析层完整建库，展示层去重重构。**

- 人物 ≠ 书：基本单元不是「一部作品」，而是「**观点族**」-- 博主会把同一观点在视频、信件、书里反复讲，**跨媒介同一观点只算一次**，不靠数量堆权重。
- **不做逐作品摘要、不做视频卡片墙**。读者要的是「这个人的思想地图」，不是 162 份视频简介。
- 全量优先：用户的典型诉求是全量（「大模型数据处理能力强」），不要擅自砍成「8-12 个代表作」。语料太大时的节流在工程层（字幕 cascade、批处理），不在范围层。

## 2. 五层数据模型（目录即契约）

```
{人物项目目录}\
  00_项目管理\      # 实施计划 / 状态 / 策略（含断点续跑规则）
  01_信源台账\      # L0 元数据：全部来源清单 + 可及性校验
  02_原始资料\      # L1 原始语料：字幕 / 正文 / 音视频（不进 git）
  03_工作数据\      # L2 来源卡 + L3 跨源综合（统一证据索引 / 主题聚类 / 关系 / 时间线）
  04_蒸馏成果\      # L4 公开表达：面向读者的 markdown 与网站数据
  05_网页\          # 页面验收报告与截图
  06_推广文章\      # 可选
  07_工具\          # 采集 / 清洗 / 校验 / 导出脚本
```

铁律：**公开内容（L4）只能由 L2/L3 生成**，不许从 L1 原文直接写展示文案，更不许凭印象写。

### 3.1 取材 cascade（P3，按优先级）

1. YouTube **人工字幕**（`subtitle.{lang}.vtt`，可直用）；
2. 自动字幕（须清洗：去词级时间标签、去滚动重复 3×）；
3. 官网/博客同源文字稿作主（博主常把信件改成视频，文字稿质量更高）；
4. 无字幕或需画面语义 → Gemini 视频多模态（`sansheng-gemini-video`）；
5. 无字幕纯音频 → whisper 转写。
**Gemini 是补全层，不是昂贵转录器**。多人访谈须补审发言人归属。B站/抖音先下载再解析。旧站分页抓取触发 429 时找官方批量接口（如 WordPress API）。

### 3.2 批次门（P4，全是大坑换的）

- **模型只许返回 VTT cue ID（如 `C0001`），真实时间码由代码恢复** -- 模型会直接编 `[00:06:81]` 或把毫秒 `.081` 误读成 80 秒。
- 批处理输出乱序：**按 request 的 video_id 映射回去，禁止按行号**。
- **一处系统性错误，整批回退**；「机械通过 + 模型自报没错」都不算数。
- 来源卡每张必带 `source_status`（`explicit` 原文明说 / `attributed` 转述 / `editor_inference` 编辑推断 / `visual_unverified` 画面未核）+ 就地锚点（视频 `timecode` / 文本全局 `line`）。
- 断点续跑靠「单卡落盘 + 批次台账」，不靠会话记忆；额度翻车（Antigravity 共享池 11/162 即限流的教训）→ 提前切 API batch（Gemini Batch：初筛 medium、精修 high）。
- **引文核实要机械做，不要相信模型自报**：把 claim 的原话与本块原文都归一化（小写、去标点、压空白）后做子串匹配；整句匹配不上就从 24 词往下逐级找最长命中窗口，命中就把引文裁到那一段。**核不上就自动把 `source_status` 从 `explicit` 降到 `editor_inference`**。Hormozi 项目实测：只做整句精确匹配是 94%，加了窗口回退到 98%，而这多出来的 4% 原本会被无谓降级。核不上的原始引文单独留一个 `_raw` 字段供审计，不入库、不上页面。
- 🔴 **两种 HTTP 400 长得一样、处理相反，必须读报文体里的 error code 分流**：
  - **并发瞬时拒绝**——同一份请求体单独重发就成功。退避时间要拉长（5 秒不够，20 秒起），否则重试全撞在同一个拥塞窗口。
  - **内容审核拒绝**（国内网关的 `SensitiveContentDetected` 之类）——**确定性拒绝，重试多少次都一样**。唯一的解是**换通道**（例如切 Gemini），不是重试也不是改文本。
  Hormozi 项目 446 个来源里有 8 个撞上后者（他讲话脏话密集、常谈钱与「退学」），换通道后救回 7 条，其中包括一条 214 分钟和一条 450 分钟的长视频。**别让国内网关的内容策略决定你的页面覆盖数。**

## 4. 中间数据结构契约（L2/L3）

- **统一证据索引**：`works.jsonl`（作品登记）/ `claims.jsonl`（观点证据，最小比较单元，带 source_status + 锚点）/ `narratives.jsonl`（自述生平事件）。
- **观点族 families**：语义归并跨媒介重复观点，保留全部证据指针；「同母稿只算一次」在这里兑现（Dan Koe: 1,836 claims → 299 families；Hormozi: 2,726 → 1,596）。

  🔴 **归并必须是「字面预合并 + 模型语义归并」两段，只做字面这一层等于没做去重。** Hormozi 项目实测：纯中文字符二元组 Dice 相似度最多合掉 22%，再往下调阈值就开始把「ROIC 复利 / 地理套利 / SaaS 留存」这种**同话题不同观点**错并到一起——精度掉得比召回涨得快。所以：
  1. 字面这一层只做**高精度预合并**（本语料标定值 0.17 合 7%、0.12 合 22%、0.10 开始错并 → 取 0.12）；
  2. 再让模型**在同主题内**按「是不是同一个主张」归并，判据要写死「同话题但主张不同 → 不合并」「一条是另一条的例子 → 不合并」「拿不准就不合并」；
  3. 🔴 **模型只许返回族 ID 的分组，不许改写任何陈述**——合并后的代表句仍由代码按「explicit > 引文已核实 > 文本长」选，模型没有机会往里塞它自己编的话。
  4. 🔴 **切批前必须按相似度把族排成一条链**。按 ID 排序切批时，一个 189 个族的主题会切成 5 批，**跨批的重复观点永远不会被放进同一个上下文比较**，模型再准也合不掉——这是召回上不去的隐藏原因，不报错、不缺字段，只体现为「合并率低得奇怪」。
  5. 归并任务的 `max_tokens` 要给足（12000 起）。跑量模型会先写一长段 reasoning，给小了会被草稿吃光，`content` 返回空字符串而 HTTP 仍是 200 —— 静默失败。
- **抽样的系统性盲区**：按视频抽样时，**只在书里讲透、视频里很少完整讲的动作会被系统性低估**——它在族归并层面因为「没人重复讲」而排到很后面，最终漏出总体蒸馏。书章全量入库只兜住了一半，另一半要靠 P7-A 拿外部解读回来对照（Hormozi 例：四类保证与问题-方案矩阵两个核心动作，都是外部解读一致强调、而内部清单里没成族的，回原书取证后补进行动模型）。
- **主题 themes**：每主题带 `central_question` + inclusion/exclusion 规则（防漏防塞）。
- **跨媒介关系**：`REPEATS / REFINES / EXTENDS / REBRANDS / CONTRADICTS / RETRACTS / ORIGIN / APPLICATION`，双向登记（A→B 有，B→A 必须有）。
- **时间线 phases**：强制三分 -- 可确认变化（有证据）/ 编辑归纳（有标注）/ 无外证因果（禁止写）。

## 5. 产出契约与密度下限（反「收敛过度」）

### 5.1 密度下限（按语料量伸缩，Dan Koe 基线 = 399 来源）

| 产出 | 下限 | 说明 |
|---|---|---|
| 核心观点卡 | 8--12 条，分 3 组归类 | 每条三段式：**大白话标题 + 两行通俗解释 + 术语对照小字** |
| 系统层（他的方法骨架） | 6--10 层 | 层名说人话，原术语作对照 |
| 行动模型 | 8--12 个 | 每个：解决什么问题 / 机制 / 步骤 / 失败模式 / 边界 |
| 时间线阶段 | 4--6 段 | 含「思想怎么长出来」演变链 |
| 内部张力 | 6--12 组 | A/B 两面 + 为什么重要 + 编辑评估 |
| 思想谱系 | 4--8 条 | 上游来源 → 他的改造 → 分类（命名封装 ≠ 首创） |

**比例直觉**：几百小时语料只蒸出几条口号 = 收敛失败，回 L3 补料，不许直接交付。读者视角三问必须能答：**他的核心思想是什么？怎么演变的？哪些点值得我学？**

### 5.2 网站数据包（10 份 JSON，与 `个人网站\web\src\data\creator-distill\{slug}\` 契约一致）

`index`（入口登记）/ `profile`（身份 + coverage + thesis + `hero_points` 导读段 + `idea_groups` 分组观点 + `evolution` 演变链）/ `architecture`（系统层 + 主公式 + 反馈闭环）/ `models` / `timeline` / `tensions`（+ risks + best/poor_fit + verdict）/ `lineages` / `themes` / `sources`（逐作品账本）/ `methodology`（去重原则 + 关系统计）+ `author.json`（作者简介，schema 复用 `enrich.md §1` 的 author_page 结构：tagline / photo / infobox / career / impact / debate / works / sources，每条外部信息带 URL）。
契约测试参照 `个人网站\web\tests\creatorDistill.data.test.ts`：计数闭环 / 引用可回查 / 关系双向 / 无全文无本机路径 / `official:false` + 编辑标签。

**第二人起新增的可选字段（Hormozi 项目定型，全部可选，老数据不填照样过）：**

| 文件 | 字段 | 说明 |
|---|---|---|
| `architecture` | `tracks[]`（`{track_id, name, subtitle, layer_ids[]}`） | 双轨。填了就必须**每一层都被且只被一条轨认领**，否则页面凭空少一块 |
| `architecture` | `bridges[]`（`{from_layer, to_layer, claim, family_ids[]}`） | 桥接层。两端必须是真实存在的 `layer_id`，且不能自己指自己 |
| `architecture` | `system_intro` | 方法体系 tab 的导语。**不填会回落到第一个人的那句**，加人时最容易漏 |
| `models[]` | `track` | 值必须在 `tracks` 里 |
| `timeline.phases[]` | `deepening` | 晚期深化说明，用来区分「话题漂移」与「前提浮出」 |
| `profile` | `seo`（`{title, description}`） | 缺失时页面回落历史默认串，所以**已上线的人不加这个字段，SEO 一字不变** |
| `profile` | `disclosure`（`{headline, items[], editorial_note}`） | 利益披露固定模块，见 §5.4 |
| `profile` | `sampling_note` / `coverage_boundaries[]` | 抽样口径与覆盖边界，页面原样呈现 |

**契约测试必须是参数化的，不能对某个人硬编码。** Dan Koe 那一版是 `toHaveLength(1)` + 路径写死 + 数量钉死，加第二个人必红。正确写法：`import.meta.glob` 遍历所有 creator 目录 → `describe.each` 跑同一组断言；数量断言一律「≥ §5.1 密度下限」而不是「=== 当前值」；`coverage` 的计数校验写成「除元信息外的数字字段相加 === works」，**不要写死 `videos+letters+book_chapters`**（第二个人可能是播客不是 Letters）。再补一条真源断言：**`index.json` 条目数 === 数据目录数且双向对得上**。

改完必须做**变异测试**确认断言真会红（多一个未登记目录 / 砍层数到下限以下 / 伪造 bridge 起点），否则你只是让它变绿了。

### 5.3 双轨建模的适用判据（什么时候该分轨，什么时候不该）

「方法论 + 人生观」这种双层结构在知识型博主里很常见，但**不是每个人都该分轨**。四条判据同时成立才分：

1. **两轨各自撑得起独立的系统层**（各 ≥3 层），否则第二轨会变成第一轨的注脚；
2. **第二轨有独立的证据配额**，不与第一轨竞争名额——抽样时就要单独设下限，否则商业内容会把它挤没；
3. **两轨之间能找出真实的桥接**（≥6 条，每条两端都能回查到一手来源）。**桥接找不出来，说明他只是换了话题，不是前提浮出**——这时应该退回单轨 + 时间线里加一段深化说明；
4. **时间上有可观察的重心转移**，且能用证据密度佐证（Hormozi 例：2024–2025 两年的个人轨证据超过前七年总和）。

🔴 **别把「他晚期开始讲人生」自动读成思想深化。** 两种解释都能解释同一批数据：想法真的变深了，或者受众结构变了（从垂直行业老板扩展到泛创业者）。判不出来就在 `uncertainties` 里写明白，不要替他做结论。

### 5.4 利益披露做成固定模块（不是可选项）

Dan Koe 项目暴露、Hormozi 项目再次确认：**这个栏目里的人几乎都卖课。** 页面不写清楚，它就是在替人做免费漏斗。

固定模块要写到「指名道姓」的程度：免费层是什么、线索入口在哪、付费产品有哪些、线下/高价合作在什么量级、以及**他的收益结构与他讲的内容之间的关系**（Hormozi 例：他讲「怎么规模化」，而他的收入来自组合公司规模化后的股权增值）。

两条纪律：
- 二手价格区间必须标「外部说法，非官方口径」，不要写成事实；
- 结尾加一句编辑说明，讲清为什么放这一段——「他的方法论质量」与「他靠它赚钱」这两件事可以同时成立，但读者有权先看见后一件。

## 6. P7-A 外部解读交叉核验（必做，本轮实战新增）

内部蒸馏完成后、定稿前，**中英文两路**搜第三方解读（书评、博主拆解、媒体报道、社区讨论、批评文章），对照内部结论做三件事：

1. **补缺**：外部高频出现而内部清单没有/讲不透的框架，回 L3 补料（Dan Koe 例：目的四层阶梯、价值四支柱、标准>目标 -- 全是外部书评主轴、内部初版缺失）。
2. **校准事实**：书名/产品史/数字/定位以公开信源为准（教训：《Purpose & Profit》被误标为「正式第二本书」，实为官网免费散文集；软件 Kortex 关停、Eden 重做被叙事美化）。「为什么火」的外部解释（如「他的生活就是论据」）必须纳入 -- 这是读者最关心的问题。
3. **找冲突**：外部批评（幸存者偏差、卖课质疑、赛道拥挤）进「局限与争议」板块，不许只放自家编辑评估。

每条外部信息带可点击 URL，核验记录落盘到 `03_工作数据\`。**先蒸馏后核验的顺序不许反** -- 先有自己的结构化结论，再拿外部解读对照，避免被二手解读带偏。

## 7. P7-B 通俗化两道闸（反「蒸馏腔」，本轮实战新增）

**闸一 · 写作规范**：
- 标题禁裸术语：「逆熵 / 主体性 / 封装 / 跃迁 / 整全 / 控制论」这类词**不许单独做标题**；一律「人话标题 + 术语对照小字」（如「管住注意力，清掉脑内噪音」对照「精神熵」）。
- 模块名说人话：**核心思想 / 方法体系 / 思想轨迹 / 局限与争议 / 依据与来源**（不用 全貌/系统/反证/证据 这类抽象名）。
- 短句关键词、图 > 表 > 文字、破折号一律 `--`。

**闸二 · 读者一分钟测试**：把首页给一个不认识此人的人看 60 秒，必须能答出 -- 他是谁 / 他回答什么问题 / 核心观点是哪几条 / 为什么值得看 / 思想怎么演变 / 我能学什么。答不出就打回重写。
**自检口诀**：这段话读给「不认识这个博主的人」听，听不懂就重写 -- 蒸馏是把知识翻译给人，不是把白话压缩成行话。

## 8. 展示层信息架构（网页，Dan Koe 定型版）

- **五个 tab**：核心思想（hero 导读四段式：定位句 / 他回答的问题 / 凭什么有说服力 / 答案骨架 → 分组观点墙 → 思想演变链 → 数字台账）/ 方法体系（系统层 + 行动模型，手风琴折叠）/ 思想轨迹（phases 卡）/ 局限与争议（张力卡 + 风险 + 适合谁/不适合谁）/ 依据与来源（数字链路：来源→证据→观点族→主题→系统层 + 去重白话解释 + 方法原则 + 免责 + 来源账本入口）。
- **作者简介子视图**：刊头金色胶囊入口，主栏经历/成就/正反评价/作品年表 + 右栏 sticky 信息卡；头像取官方渠道（YouTube 频道头像优先），裁方 240px、≤50KB、带 credit。
- **视觉与交互**：暖纸 tokens（与书籍蒸馏详情页同源）；卡片式逐级深入，**不做一屏拉不到底的长页**；手风琴卡片带 +/× 指示，两列布局同排联动开合；390px 无横向溢出。
- **双轨与桥接的展示**（有 `tracks` 时才出现，单轨数据完全不受影响）：方法体系 tab 内按轨分组，每组一个轨头（名 + 副标题）；桥接单独成块「两轨怎么咬合」，每张卡是「个人层名 → 商业层名 + 一句咬合判断 + 一手来源数」；行动模型同样按轨分组，但**编号跨组连续**（读者说「M07」时指的是同一个）。桥接块用两列网格，390px 下降为单列。
- **渲染责任**：skill 只产数据契约（§5.2）；Astro 页面实现与部署归 `sandy-website`（动态路由已存在，新增人物 = 加数据目录 + 登记 index.json）。

  🔴 **「动态路由已存在」不等于「不用改页面」。** Hormozi 项目实测：路由确实会自动遍历 `index.json`，但页面正文里刊头统计胶囊、信源构成句、来源库类型筛选器、免责声明里的人名、SEO 标题与描述**全是按第一个人写死的**。加第二个人必须先把这些收口到一个共享的标签映射模块，由**数据里实际出现的键名**驱动。
  验收方式是**比对构建产物**，不是读代码：改完之后第一个人的 `<title>`、`description`、统计胶囊、信源构成句、关系卡必须与改动前一字不差。

## 9. 数据流与维护规则

- **上游 L2/L3 是真源**；公开 JSON 由导出器（如 `07_工具\export_website_data.py`）生成，**每次运行全量重写 -- 手改公开 JSON 会被覆盖**。
- 展示文案的修改（包括 P7-B 人话改写）**必须落到导出器模板或上游数据**，只改下游 = 下次导出全丢（本轮实战的实际教训：人话改写直接改了公开 JSON，上游未回写）。
- 版权边界：不公开完整字幕/信件正文/书籍原文；公开页只留编辑摘要、分类、证据定位与官方来源入口；标「编辑归纳，非官方观点」；谱系只作编辑分类，不作法律结论。
