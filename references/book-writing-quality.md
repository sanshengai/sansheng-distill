# 普通书：把质量放进写作，不靠追加审稿轮次

普通单书的写作真源。reader/guide 的流程和字段仍按各自路线；明确要求严格逐项覆盖时用 high-retention-books.md。本页不增加一套审核、知识分母、故事账本或正式收据。原书事实与观点默认作为来源，外查范围只在 SKILL.md 定义。

## 1. 篇幅：由内容决定，字数用于发现写薄

不设通用的“每书几万字”“每章800字”或原文保留比例。已经明确给定的产品档位下限仍由实际消费者执行；不能绕门，也不把严格档或某批管理书的比例迁给普通新书。

写前按有效来源规模和章的类型分配输出空间：案例密集章留给关键故事，论说章留给推理与条件，短序言按实际内容写。输出上限不足，先按完整论证边界拆任务，不把一个长章压成几百字。只有首次采用新模型、提示或压缩策略时，用一个真实复杂组验证可装配、不断尾；这个组直接计入正式成果，不另造试写版。

本地汇总每章来源规模、正文字数、空章/缺章、截断状态。异常短、突然变薄或异常接近原文只提示对应章节的制作问题；比值不是信息保留率，不作为整书重写的充分理由。核清是否只是短章、图为主要信息或语言换算差异；有实际遗漏只补缺口，完整短章不注水。

## 2. 故事：保留它怎样发生，以及它为什么支撑观点

从原书真实关键案例里写出：谁遇到什么困境，采取了什么行动，哪里发生变化，结果怎样，作者借此说明什么。不是每个故事必须齐五格；原文没写时间、对话或结果就不补。保住改变理解的具体动作、转折和条件，不把“某家长这样做后成功”当成完整故事。

案例放在它支撑的论点附近，论点和案例之间有解释。次要同义例子可以压缩；本书独有且承担论证的案例不能因为跨书重复而被删。漫画和机制图若承担关键步骤，接入实际图片或依实际图意转述，不只记“这里有一张图”。纯理论章用完整推理，不硬编故事。

## 3. 观点：讲清作者为什么这样说，不把所有书写成同一套话

优先保留主张、理由、案例/证据、反例或适用条件的关系。避免把正文写成“理念一句＋编者比喻一句”的卡片串。

区分作者自己的判断、作者转引别人的观点、编者组织材料的归纳。作者的价值主张可以作为主张呈现，不能擅自加成科学定论；观点可以尖锐或有争议，不因与常识不同就改温和，不替作者升华到他没有说过的结论。历史案例按书中时点写，不悄悄改成当下现状。

比较和批判有书中依据才展开；没有明确反方、争议或独立书评时按消费者允许值留空，不为填满模板编对立。原书观点与编者分析分开，说明一次必要边界即可，不给每段重复加审计和免责声明。

### 3.1 先让读者走通一条论证，再展开细节

先明确这一章要回答的问题、作者的答案，以及哪些推理或案例使答案成立。把它写进已有写作任务，不另生成论证账本。章节标题和摘要先显出这条主线，正文再展开；开头可预告结论，不先写一遍完整推导、随后再重复展开。不能把结论单独抽出后删掉让它成立的条件。

同一段承担一个主要解释动作：提出困境、解释机制、推进案例或说明限制。条件紧贴相关结论；次要时间节点、同义例子和出处信息按其作用取舍，不让读者在理解机制之前先记一串年份与数字。必要的底本冲突集中就近交代一次，不能隐藏影响判断的差异，也不把查证过程写成每段的收尾。

按书的实际论证方式组织，不强制所有章节套同一模板：

| 内容类型 | 优先讲清的顺序 | 避免 |
|---|---|---|
| 案例与故事 | 困境、关键行动、转折、结果、作者用它解释什么 | 先堆年表，再用一句空泛道理收尾；补造对白与情节 |
| 理论与教材 | 问题、必要定义与假设、推导关键步、代表性算例、结论及失效条件 | 把定义列成词典；先完整概述再完整推导；删掉决定结论的中间步骤 |
| 财务及其他技术方法 | 要比较什么、采用什么口径、关键计算、结果意味着什么、何时不适用 | 按表格逐格改述；只给公式或结果而没有解释 |

长章在问题或推理阶段改变时给出阅读转折。实际消费者支持正文小标题时用能说明问题或结论的标题；不支持时用清楚的过渡段，不把 Markdown 标题塞进只接收纯文本的字段，不自行扩 schema。小节标题也不替代原书章节身份。

术语首次出现给一句必要的白话解释，之后沿用一致名称。主体未变时用明确承接，避免每段重复完整作者名及“作者指出”。不用“核心在于”“值得注意”代替因果解释，不强制每段短句或固定字数。

### 3.2 公式、图表与习题：保住意义，分清作者给了什么

承担论证的公式须就近说明变量、单位、时期和成立条件，并解释输入变化如何影响结果；原书有代表性算例时保留关键步骤及结果含义。图表说明比较对象、轴或口径、关键变化及其论证作用，不逐项抄数，也不只写“见图”。不能为了口语化删去公式、边界或改变数字。这是写作要求，不自动启动数值重算或书外核验。

题设、原书解答、编者新增算例分别归属。原书只给题目时保留问题、必要数据、假设及真实交叉指引，不生成作者口吻的答案；没有答案不算制作缺陷。用户另要求解题时按其授权交付并标明编者计算，不混入原书观点。习题、术语表和附录保留来源身份；若当前消费者支持辅助部分，可与主论证分层，否则以明确标题和承接区分，不能静默排除实质内容。

## 4. 一次写作的任务要求

给写作任务：目标章/完整论证组的来源、必要邻段、作者/转引者身份、实质图意与最终消费者的最小字段。要求连续正文、主论证及关键案例、条件和反例在正文里讲清；不要另生成同规模的“理解层”，不要让模型重抄整份来源ID列表。

在同一个 `job.task` 中带入本组要解释的问题、适用的上述写法，以及接续位置。分片任务给前一片结尾和本片必要邻段，明确哪些内容已经展开；续片从新问题或未完推理接着写，不再介绍整章、重复定义或各写一个结论。相邻片段接续在装配时处理，不把相邻原文重复写两遍。

速览、全书地图、核心卡片和行动清单从权威正文派生；没有材料的可选模块按真实契约留空。同一本书由一个负责人贯穿生产与装配；多路请求分完整组并保留前后承接，避免每组重写同一引言。

派生摘要回答“本章主张什么、为什么、关键条件是什么”，不列一串主题词。串读章标题和摘要应能把握全书如何推进；正文仍能独立连续阅读。只有首个复杂组或新表达方式需要标定时，把主线是否只展开一次、关键机制是否完整、细节是否分层一起看；该组直接计入生产成果，不另写样稿或追加全书文风审阅。

普通书默认 production_only：质量要求在写作与装配时完成，不追加内容复审。只对已发现的缺章、乱码、断尾、图片错位或功能错误定点修复。用户另要求内容审阅时，一次有明确范围的审阅即可，修后只检查变化；严格档单独按其契约。
