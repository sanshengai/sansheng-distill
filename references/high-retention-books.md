# 单书高保留知识契约

适用于深读档的书（定档见 §0）以及明确要求保留一本书大部分知识的任务。沿用书籍 Step0–Step7，在起稿前增加来源盘点，在理解层之外增加深读层；不把现有每章讲书稿当成完整知识保留。通用证据契约与校验器由本 Skill 持有，产品端另负责信息架构、页面与发布。

## 0. 默认路线：书怎么蒸，不再逐本商量（2026-09-23 sandy 定，七本管理书实跑后固化）

用户只说「蒸馏这本书」「把这批书上线」时，按本节的档位、参数和顺序直接执行，交付时报告定档与取舍；只有本节没覆盖的情况才问。用户明确给了比例、范围或档位时以用户为准。

### 0.1 定档

| 档 | 适用（按顺序判断，先命中先用） | 做法 | 页面 |
|---|---|---|---|
| **深读档** | 板块的核心经典、主干书；用户点名要「完整保留」 | 本文件全部契约：先冻结知识分母，再写深读，逐项覆盖审阅 | 横幅标「深读版」（config `edition_label: "深读版"`） |
| **导读档** | 同一作者的第 2 本起；实操手册类；出版超过 15 年且观点已被后来的书吸收；用户只要「上线一批」且没点名核心书 | 章级导读（SKILL.md Step0–Step7），每章篇幅按原章字数比例定，**不写死 800～2,600 字** | 不标「深读版」，不冒充完整保留 |

拿不准时按导读档先上线，把书名记进产品工作区的「候选升级」清单；已上线导读档的书只在确认值得时升级。

### 0.2 默认参数

| 项 | 默认值 | 说明 |
|---|---|---|
| 知识点密度 | 归并后每千字有效原文约 **3～4 条**，仅作异常提示 | 七本实测 3.9～4.8；超过 5 条先逐对查重复，同一论证的原因—动作—结果可合并。独立机制、案例、限制和图意不能为了压到数字而删掉 |
| 核心（critical） | 约占 30%～40% | 核心观点、改变结论的条件与限制；核心项必须 100% 讲到 |
| 深读篇幅 | **不设字数目标**，以知识点讲全为准 | 实测约为有效原文的 65%～75%；低于 50% 或高于 90% 视为异常，先查是否漏讲或照抄 |
| 深读单元 | 按原书小节装，每单元约 10～14 条知识点、1,500～3,000 字 | 单元标题是论点句，不用「第 N 节」 |
| 理解层 | 每个阅读部分 ≥ 800 字 | 原章本身不足 800 个非空白字符的走 §5 短附记规则，不为凑字加内容 |
| 图表 | 全部实际看图并写图意 | 表格逐行转写；印刷异常据实保留 |
| 默认排除（写理由） | 中文版推荐序、出版方阅读指南与讨论题、致谢、版权页、目录、索引、只有出处的尾注、译者单位换算注 | 用户要求保留时改为有效 |
| 默认有效 | 作者本人的前言、导言、部分导言、结语、后记，有实质内容的附录（研究方法、数据表） | 附录单独成阅读部分 |
| 疑似译误 | 按译文保留，在深读里加一句标注 | 不按常识擅改原文 |

### 0.3 固定顺序：先出知识点，再写正文

**为什么先知识点、后章节**：第一、二批按章节直接写讲书稿，正文只有原文的 7%～14%，而且无法回答「漏了什么」；先把全书知识点列出来冻结成分母，写作和审阅都对着分母，漏讲能被逐条查出来。

1. **取书与定档**：核版本（出版社、年份、ISBN），生成 `book.txt`，按原书目录切来源章并判有效/排除（§0.2 默认排除表），按 §0.1 定档。
2. **来源盘点**：规则切段；短行交机器分诊，主控复核排除项；所有图拼成对照页实看并写图意。
3. **知识清单（分母）**：写作模型按小节抽取（每个有效段至少进一条）→ 按块归并同一论证的重复表述；密度偏高时先找真实重复，不作数量硬裁剪 → 机器忠实度检查一轮 → 主控审被标出的条目并随机抽 10% → 修补一轮 → 冻结（有效段全有去向、图段由 figure 类条目承接，反过来每条 figure 类条目也要整张承接一张图）。
4. **写深读并先审事实**：按小节装单元逐条讲全 → 本地检查照抄、元话语和内部编号；可定点修的地方不整单元重写 → 对深读**全部句子**跑一轮机器事实审计（人物、数字、因果、真实与虚构、观点归属、凭空树靶子、加戏）→ 主控逐句复核被改的句子（审计模型也会编造；删掉的内容能在原文找到的先不落稿，见 §6.6）→ 按句式扫描复述式加戏 → 合著书全书搜作者名，共同主张写成「作者」。
5. **覆盖检查与定点回审**：在事实修订落稿后才做首轮全量覆盖 → 补写一轮 → 只复查正文变过的单元。机器报「正文和知识项冲突」时先回原书核对，错误可能在知识清单；改清单要更新冻结哈希并复查受影响单元，不能为过关把正确正文改错。若为修分母而重新执行 freeze，须再执行 link 恢复 `target_ids`；覆盖结果 `checked=0` 视为流程失败。补写新增的句子再做定点原文事实核对，不能把首次全句审计的绿灯沿用到新句子；装配后只重判正文或知识陈述哈希变化的单元。
6. **装配**：旧导读沿用，只为新增阅读部分补写理解层；没有旧导读的新书用 `assemble_new_chapters.py` 逐有效来源章产出待审章节草稿。超过 6 个深读单元的章节，主控用单元标题/摘要逐一对照草稿，补齐遗漏的主要主题群；模型输入覆盖所有单元不等于输出覆盖。新写的理解层按来源章逐句做一轮事实与加戏审计，主控逐条裁决模型标出的改句、删句；只改有问题的句子，不为少数建议重写整章。理解层与原文摘录分开验收：摘录逐字找不到时保留合格理解层，回原章定点换成真实短句，复核摘录注释是否仍对应；只把缺正文或正文不合格的章节重新派给模型，不能为了摘录的引号和标点差异整章重写。书级综合先将各单元压成一行并限定每个输出字段的字数，避免一次塞入全书正文或超大 schema 导致 `INCOMPLETE:length`；失败仅重派该项。卡片挂真实深读单元；若站内阅读部分与原书章号不同，锚点明确写「站内第 N 章」，来源另保留原章标题与原文行号，不把站内编号冒称原书章号。
7. **签署与放行**：主控抽检（高风险句 30 句对原文；正文删改掉的说法在分母里是否还写着；讲全项随机 10%）→ 签署 → `book_coverage.py` 退出码 0 → 渲染 → `verify_high_retention.py` 全过 → 用 Read 看截图（首屏、桌面与手机展开的深读单元）。
8. **上站与沉淀**：发布到网站、更新跨书索引；在产品工作区（如 `一页/管理/`）追加工作日志、更新书目进度。

### 0.4 审阅预算：每类检查一轮，不为分数反复重跑

- 忠实度、事实、覆盖三类检查各跑**一轮全量初审**，修补后只复查改变过的部分；忠实度不再全书跑第二轮。若知识项抽检的推断/结构错误率超过 5%，按 §6.3 做必要的全量知识项审计，逐项裁决建议。
- 深读初稿的照抄与元话语交给定点 polish；只因解析失败、正文过短、空摘要、标题不合格或内部编号泄漏重写单元。模型未列全 `covered_item_ids` 不能直接判漏讲，交给后续逐项覆盖检查。
- 新书理解层的句审单独计账，不拿深读的事实绿灯代替。全章输入原文窗口、全部待审句，一章一 job；审计只出建议，主控核归属、数字、因果和新增情节后局部落稿。《目标》42 章一轮 197,308 输入 / 88,482 输出 token，标 188 处，说明该轮成本高但有质量收益；后续若先验抽样表明标出项多为误报，可缩小检查范围，但不得静默跳过新增正文。
- 每本记录阶段 job 数、模型输入/输出 token、墙钟耗时和重试数；看回执而非凭体感调并发。已在跑的批次不为提高并发而重启；下一阶段在共享套餐额度和失败率允许时提高并发，输出目录已存在时沿用回执、只补真正缺失的 job。
- 读图初稿也逐图保存模型 usage、耗时和尝试次数，成本复盘注明调用范围。旧回执没有 usage 就标「未知」，不得为了补成本账重新调用已审图；图意仍须对着原图人工裁决。
- 批量审阅的超时按该模型近期调用分布设置，不沿用过大的通用上限：一次实跑中位 17 秒、p95 38 秒，单个故障调用等约 12 分钟才退出。此类任务可先用约 180 秒超时，超时只定向重派；多项同时超时先查服务端拥塞。
- 主控只审机器标出的问题项，再随机抽 10% 作抽检；抽检错误率超过 5% 才扩到该类错误的全书检查。
- 不为「分数刚好在线附近」重复调用；机器判定讲全、主控抽检也没问题的，就按这一轮签署。

## 1. 保留的对象与分母

“保留 80%–90%”指独立知识内容的覆盖，不是复制原书相同比例的句子、字数、情节或版面。至少盘点观点、定义、推理、证据、案例机制、方法步骤、限制条件、反例、图意及实质附录。只有中心思想、没有论证与实施条件，不算完整保留。

此档默认目标：全书完整覆盖至少 90%，每个有效原作章节至少 80%，核心观点与改变结论的条件/限制 100%，有效来源段落去向 100%。盘点时将这些核心观点及条件/限制标记为 `critical`。用户明确要求更高时使用更高目标；当前 CLI 使用上述固定阈值，更高目标须另核报告中的实际比例，不能只凭退出码 0。`partial`、`missing` 不计完整覆盖；排除项必须逐项说明理由并人工审阅，不能为提高比例删掉难写内容。

覆盖前先确定分母。来源盘点完成后冻结信息项的 ID、类型、原作章、源段集合、关键性和知识陈述。允许合并重复阐述，但应保留来源并集与合并理由；重复案例包含新的条件、推理或失败机制时不可整体删除。字数比只作诊断，不能替代知识覆盖判断，也不为短而完整的论点填充废话。

冻结后发现分类、定位或遗漏错误，登记 before/after、旧新摘要、理由与审阅者，保留旧快照并重审受影响映射。不得静默改写冻结摘要，或删掉缺项后宣布达标。分母冻结是防止事后挑选，不是要求保留已证实的来源错误。

`inventory_amendments` 是人工审计记录，校验器不验证修订审批或旧快照。逐项 `review_sha256` 绑定知识项及其目标正文，不包含来源文件哈希或段坐标；来源版本或定位改变时，必须撤销受影响签署、重新对源审阅。重新设置基线后的机器通过不能替代纠错批准。

## 2. 先证明读到了什么

1. 对照实际书源核书名、作者、译者、出版信息、ISBN 与版次，检索页年份不代替版权页。记录源文件与转换文本 SHA256。
2. 逐项核对目录与正文；电子书按实际阅读顺序核章、节和文本，不能只信转换器的标题检测。扫描件先定位 OCR 缺失。作者前言、实质附录、脚注与图表不得无声遗漏。
   电子书删了图、连图题行都没有时，回扫描版逐页识别（按「图 x-y」一类图题搜页码）补图；底本里没有图题行的图挂到第一次提到它的正文段上，该段仍按正文处理、读原文时段后附图意。补不回的缺页、粘连的行、中译本编者附加的内容，写进质量报告的局限，不静默处理。
3. 来源结构与网页阅读结构分别编号。原书四章整理成七个阅读部分，不能把后者写成原书七章。
4. 全文以稳定源段 ID 和 Unicode 字符半开区间定位。每段声明有效或排除及理由；有效段至少连到一个冻结知识项。
5. 图片以完整资源路径、扩展名、资产 SHA256、出现位置识别。同编号的 PNG 与 JPEG 可能是两张完全不同的图；同图多次出现仍登记各次位置。

模型可提供盘点候选，不自动决定分母。审阅者需要读对应来源，检查候选的遗漏、重复、主体、条件与因果方向。纯标题、版权、重复图等可以排除，但不能根据短段、文件名或页数自动认定没有知识。

## 3. 图表与体裁

先实际看图，再结合邻近文字解释。记录轴、单位、图例、方向、范围、非比例示意及不确定之处；数值印刷异常据实保留，不能按常识擅改。图意未审时保持 pending，不把占位符当成已解释。完整图册的审阅与单图解释分别签署。

对正反信号、条件或分类表，先在私有审据中逐行转录列名与关键原句，再写独立解释，重点核对“不”“不得不”“仅”“至少”等改变方向或范围的词。复核者重新打开原资产，不能只检查上游已经签过的图义；邻近正文的例外应另标出处，不可倒写成图中文字。发现图义错读时，沿图义、知识项、深读、理解层检查传播范围，保留旧审据，纠正后重新绑定受影响的签署。

公开表达优先使用独立解释和必要的原创关系图，不默认重刊原书图表或整份问卷。自绘图不能增加原书没有的因果、顺序或测量精度。对表格按行核对，对步骤检查前提与依赖；图里的五层结构不自动意味着只有一条线性的修复顺序。

| 书型 | 深读单位与重组方式 |
|---|---|
| 论说型 | 定义、主张、理由、证据、反例与适用范围组成一个论证单元 |
| 方法型 | 决策与操作依赖，保留触发条件、步骤、资源及失败边界 |
| 管理寓言 | 提取问题、行动、反馈与管理机制；明确虚构性质，不将完整剧情重述当知识覆盖 |
| 商业史 | 时间和外部环境串联选择与后果；后来的事实与作者当时判断分开 |
| 图解型 | 文字与图意共同盘点，关系图与解释一起验收 |
| 书信/讲话合集 | 保留每篇日期和出处，再按议题组织；不抹去前后观点变化 |

一个单元可覆盖多个来源段，一个知识项也可由多个单元共同解释。不要把逐句换词、长篇对话改述或按原顺序近乎重写全书当成高保留。

## 4. 审阅与机器校验分工

正式目录的公共数据契约：

| 文件 | 用途 |
|---|---|
| `source-map.json` | 源哈希、原作章/节/段范围、排除理由、图像资产与图意审阅、冻结摘要 |
| `content-ledger.json` | 独立知识项、关键性、来源、covered/partial/missing/excluded、目标正文 ID、语义审阅 |
| `deepread.json` | 具有稳定 ID 的深读单元、标题、摘要、正文与源段集合 |
| `coverage-report.json` | 各章/类型/关键项覆盖、缺项清单、结构与语义/图像审阅的分别结论 |

源文件与原图留在私有资料区，不随网页投影。哈希、位置和独立解释可以进入审计资料；不要把私有绝对路径或全文元数据插入公开 HTML。

机器核来源位置、哈希、集合、分母是否变化、正文是否存在以及声明比例。**机器不能判断知识是否真的解释完整。** 语义 reviewer 必须实际审阅来源与目标正文，再记录判定、理由及绑定该正文的摘要；正文变更后旧签署失效。模型输出里的自评、HTTP 成功或传输完成都不是语义批准。

除逐项覆盖审阅外，每本至少抽查 10% 单元的人物、关系、时间与因果，高风险数字、否定、适用条件优先。发现错误超过被抽检断言的 5%，扩到该错误类型的全书检查；必须说明抽样分母与实际范围，不能只写“人工看过”。叙事结果与作者的因果解释分开，寓言不能当成对照实验。

运行公开入口：

```sh
python3 "$SKILL/scripts/book_coverage.py" --book-dir "$DATA/<slug>"
```

退出码 0 表示本脚本所检查的数据契约通过；2 表示 `machine_pass=false`；3 表示机器检查通过，但来源/语义审阅或待核图意尚未放行。待核图意造成完整覆盖不足也可能返回 3。上述 10% 抽检记录不由本脚本核验，须另行验收。报告中的 `release_ready` **只涵盖这套数据契约**，不表示页面、外部事实、索引、产品验收或网站发布已经完成。有效章、有效知识分母或正文为空时必须拒绝；改正文保留旧签署、漏图、漏源段也必须能被拒绝。精确字段及哈希算法以 `scripts/book_coverage.py` 与合成反例测试为唯一实现。

## 5. 三层阅读与页面放行

- **速览**：独立撰写的论点标题与摘要，串起来能看懂本书解决什么、如何推理。
- **理解**：现有章节讲书稿，解释整体结构与关键机制。
- **深读**：完整展开的论证、证据、案例机制、方法及边界；内容来自已审知识项。

先组织主题和论证，再决定折叠。不能把一大段正文藏进 details 就声称完成分层。导出单独的标题速览文件供阅读审查。

理解层另做主题完整性复核：对照原章的小节、问答及主要异议，确认读者能看到每组问题的入口与相互关系。下层逐项 covered，不代表上层没有偏题；例如一章讨论多个问题，不能只展开其中一个而仍用整章标题。允许不同层次详略不同，但不能靠深读中“已经有了”来掩盖理解层对原章结构的失真。

全局观点、概念、行动与自检卡应显式关联真实深读 ID；避免从“第 N 章”文本猜跳转。点击必须打开目标标签、阅读部分与折叠单元，滚动位置不能被悬浮导航遮住；初始 hash、切换标签后再次点击同一 hash、手机尺寸都需测试。

渲染须沿用正式五板块骨架与完整交互。直接填骨架与基于已验收成品替换数据是不同的输入契约：后者不能误把未填骨架当成成品。所有继承数据槽必须替换或按契约降级，尤其是公式、作者、评价、延伸内容和隐蔽子视图。仅路由合成测试通过不代表真实书页通过。

新增字段须沿用统一 HTML 转义、标点/破折号与公开来源格式规则，不能绕过旧字段已有的格式处理。

高保留页面使用完整入口：

```sh
python3 "$SKILL/scripts/verify_high_retention.py" --book-dir "$DATA/<slug>"
```

它在整本书上执行原 `verify_page.py` 的 HTML、distill、源文与浏览器检查，现场复算知识覆盖，并检查全部有效来源章、阅读部分、深读单元的映射和实际 DOM 正文一致。不能提交删去附记的临时子集来验收。`--skip-interact` 只供排错，报告会标明未检查浏览器；不构成 Step7 完成。批量时显式声明预期名单、逐本运行并检查每本退出码，不以已存在目录推断名单。非高保留书仍沿用原 Step7/批量入口。

**短来源附记的有限长度规则**：真实来源本身不足800个非空白字符的致谢、编辑背景等，可保持信息完整的较短理解层。不能因标题短、字数少或标记成“附录”自动豁免。实质论证、方法、病例与对话附录仍按主内容验收。需要人工完成 `short-apparatus-review.json`：`schema_version: 1`，`input_sha256` 绑定 `book.txt`、`source-map.json`、`content-ledger.json`、`deepread.json`、`config.json`、`distill.json` 六份实际文件，`entries` 逐项记录阅读部分 `no`、`source_chapter_id`、`reviewer`、`decision: approved`、`rationale` 和全部 `knowledge_item_ids`。

该来源章必须为已审的 `effective`、`source_scope=non_primary`；对应 config 的 `source_role` 只能是 `source_apparatus` 或 `editorial_context`。来源与正文都不得为空或只有标点，该章每个知识项须完整 covered，来源和语义审签均有效，理解层与深读仍完整显示在网页。满足这些条件时，入口只接受该阅读部分的精确 G9 下限差异，G14 引文、定位及其他全部错误仍会拒绝。回执不由工具自动签署；哈希只发现审阅之后的变化，不能替代人工判断其是否真为附记。机器报告列出所有采用该规则的部分，不将其伪装成800字。

逐本另核所有单元可达、桌面/手机截图和五板块的真实书籍身份。对新增检测使用被测入口上的失败反例。最后再完成跨书索引、产品适配与发布；三者不能由 coverage 的绿灯替代。

## 6. 审阅分工：方舟初审 + 主控审标出项（2026-09-23 停用 Jev 后）

§4 要求语义审阅「实际审阅来源与目标正文」。逐项人工审几百条知识点是深读档最大的开销，所以改成**方舟 Coding Plan 按单元批量初审，主控只审被标出的问题项并随机抽检**。初审模型只判断、不代写结论；它和写作模型是两次独立调用，但同属方舟，**不能当作独立第二意见**，主控抽检是兜底。

### 6.1 流程与分工

| 步 | 谁做 | 做什么 | 留痕 |
|---|---|---|---|
| 来源盘点 | 规则 + 方舟 | 注释编号、网址、图占位、图题、目录标题用规则判；≤40 字短行每 40 行一次交方舟分诊 | 分诊报告 |
| 排除复核 | 主控 | 逐条看排除建议；常见误判：**被斜体书名断开的正文碎片**、**排在图前的表题**、**书内小标题被当成排除**、编者单位换算注 | 覆盖表（行号 + 理由） |
| 读图 | 主控 | 所有图拼成对照页实看；高亮变体逐张核对；表格逐行转写 | 图意签署 |
| 候选知识点 | 方舟 | 按小节抽取（每个有效段至少进一条）→ 按块归并真实重复；3～4 条/千字只用于提示复核 | 候选与归并报告 |
| 忠实度 | 方舟 → 主控 | `upgrade_check.py faithful` 每块约 25～30 条一次，标出来源过窄/加戏/不符/据标题编造/审核备注混入；`--apply-pids` 补相邻来源，其余重写一轮；主控审标出项 + 随机 10% | 删改记录 |
| 冻结 | 脚本 | 有效段全有去向、图段由 figure 类条目承接；写分母哈希与如实的审阅方式 | source-map |
| 事实（先于覆盖） | 方舟 → 主控 | `upgrade_check.py fact` 对初稿**全部句子**逐句判定（人物、数字、量词、指代、因果、真实与虚构、观点归属、加戏）并给改正句；主控逐句复核被改、被删的句子；另抽检含人物/数字/量词/指代的句子，错误率 >5% 时对命中单元定点再审一轮 | 审计记录 |
| 覆盖（事实修订后） | 方舟 → 写作 → 主控 | `upgrade_check.py coverage` 每单元一次，列出没讲全的条目和缺了什么 → revise 补写一轮 → `--reuse` 只复查补写过的单元；补写句子定点事实复核；主控审仍未过的条目 + 随机 10% | 覆盖结果、人工签署 |

### 6.2 签署规则

- `semantic_review.reviewer` 如实写：方舟初审判定讲全的写「方舟 <模型> 覆盖初审；主控随机抽检 N 条」，主控逐条核对的写主控与理由。不把机器通过写成人工审定。
- 签署绑定判定时的正文（`passage_sha`）；判定之后正文又改过的条目不签，重跑该单元的 coverage（`--reuse` 只重跑变过的单元）。
- 抽检分母写清楚（抽了多少、从哪个池、发现几处问题），记在 `quality-review.json`。
- **调用失败不是判定**：任何一次调用重试后仍失败、或模型漏判某条，整轮拒绝写结果（`.partial.json` 另存），不能把缺结果当成「讲全」或「有问题」。
- **产出缺失同样不能静默**：抽取重派后仍有有效段落没有知识点、写作重试后仍有单元缺正文/摘要/标题，都以非零退出并逐块点名；只写进报告、退出码 0 的「部分失败」会一路走到冻结或渲染才暴露。内容审核拦截（如方舟 `SensitiveContentDetected`）重试无效，要单独点名，由主控读原文补建。

### 6.2a 方舟初审的实测能力（《绝对坦率》副本人为注错，glm-5.3-flash，一本书一次运行）

| 检查 | 查出注入错误 | 在未改动内容上的标出率 | 说明 |
|---|---|---|---|
| 覆盖 | 27/30（90%）；整句删除 19/20，只删关键条件 8/10 | 7/592（1.2%） | 对「只丢一个条件」不够敏感 |
| 忠实度 | 20/20 | 47/854（5.5%），多数理由站得住 | 标出项主控必审 |
| 事实 | 16/30（53%） | 240/2,253（10.7%），多为「结尾总结」类加戏 | **细粒度错误（人称、量词、把原文扩成框架）常漏**：没被标出的句子不等于已核实，主控抽检不能省；加戏标得偏积极，删句要从严复核 |

事实检查换模型对比（同一副本、同一提示）：glm-5.3 查出 18/30、误标 12.7%；doubao-seed-2.1-pro（Agent Plan）21/30、误标 16.0%、慢 3 倍多。默认保留 glm-5.3-flash——多查出的几处换来的是一半以上的额外人工复核。**某本书抽检事实错误偏多时，对命中的单元用 doubao-seed-2.1-pro 定点补审一轮**（`--gateway agent --units …`），计入审阅预算。

### 6.3 试点实测的分母错误（冻结前逐类排查）

1. **据标题编条目**：模型会把章题、小节标题、过渡句（「现在我们来讨论这些象限」）写成知识点，甚至编错（把第 4 章说成「第四部分的主题」）。章号、章题、副标题行一律排除，据此生成的条目删除。
2. **尾注出处当知识**：只有书名、出版信息的注释不是知识。
3. **图意并进别的类型**：图段落必须由 `figure` 类条目承接，否则 `book_coverage.py` 判来源审阅未完成；混合条目拆开。
4. **statement 夹审核备注**：「续见某节」「后文详述」「此处被再次强调」这类给审核者的话必须写进单独的 `review_note` 字段；夹在 statement 里会让判别模型误判、也会误导写作。
5. **编号泄漏**：段落编号（p1254）、知识点 ID 混进文字；正文同样要查。
6. **来源标得太窄**：概括了相邻段落却只挂一段——忠实度检查标出的最常见原因，补相邻来源即可。

### 6.4 正文常见事实错误（事实审计实测）

张冠李戴（把引用人物的观点算到作者头上）、把真实公司/人物标成虚构、凭空树一个「很多人认为……」再说作者反对、上下级角色写反、「两个案例」实为一个、条目数与原文不符。**事实审计模型给出的「改正句」同样可能编造**（试点中出现过把一条原文没有的「第五条法则」换成另一条编造的内容），改动必须由主控对原文复核；覆盖分数突降往往是信号。

### 6.6 审计的原文边界与删减取证（2026-09-24 第二轮 11 本）

对照原文找错的审计模型，只拿到「条目引用的那一段」或「单元依据段」时，会把依据在相邻段、被译者注或图题隔开的数字、案例、原因判成「原文没有」而建议删除——第二轮里至少出现在五本书上，全靠主控回原文恢复。两条做法：

1. **给够原文**：条目审计与逐句事实审计都附同一小节里依据段前后各一段「相邻原文」，提示词写明在相邻原文里有依据的不算加戏；挂在正文段上的图，读原文时是「正文 + 段后图意」，不能用图意顶替正文。
2. **删减先取证**：每条改动删掉的片段（数字+单位、三位以上数字、逐字 8 字以上）回全书原文搜；搜到了就带段落号标出，事实审计不自动落稿，主控核实确属加戏或错误才采纳。回测：被主控驳回的误删约九成能标出，被采纳的建议约一成被标，复核负担可控。取证抓不到换了说法的删减，逐条复核仍不能省。

### 6.7 成本参考与实现

七本管理书（2026-09-23）：分母 449～1,270 条/本（3.9～4.8 条/千字），深读 7.4 万～20.9 万字/本，全程 1.5～5 小时/本；各书事实抽检错误率 7.5%～16.7%，全部经过全句审计与主控复核。

参考实现在 Cowork 仓 `读书蒸馏/management-tools/`，命令顺序与审阅预算见 `UPGRADE-RUNBOOK.md`：source_map（扫描件找图 pdf_figures）→ inventory → consolidate → check faithful（只一轮）→ rewrite_items →（audit_items）→ freeze → deepread write/polish → link → check fact → 主控裁决 + samples fact/fragments → check coverage → deepread revise → 补写句定点事实复核 → check coverage --reuse → assemble（新书章节走 `assemble_new_chapters.py`，旧书走 `upgrade_assemble.py`）→ samples covered → sign → render → shots。装配后若正文或分母变化，只按哈希复查相应单元并更新签署。发布用 `publish_booknote.py`，上线收尾（i18n 计数、线上核验、工作日志）用 `upgrade_closeout.py`。页面模板参照一律用冻结副本，不引用别的书正在用的活页面。产物与本文件 §4 契约一致，最后仍以 `book_coverage.py` 与 `verify_high_retention.py` 放行。
