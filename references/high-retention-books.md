# 单书高保留知识契约

适用于明确要求保留一本书大部分管理知识的任务。沿用书籍 Step0–Step7，在起稿前增加来源盘点，在理解层之外增加深读层；不把现有每章讲书稿当成完整知识保留。通用证据契约与校验器由本 Skill 持有，产品端另负责信息架构、页面与发布。

## 1. 保留的对象与分母

“保留 80%–90%”指独立知识内容的覆盖，不是复制原书相同比例的句子、字数、情节或版面。至少盘点观点、定义、推理、证据、案例机制、方法步骤、限制条件、反例、图意及实质附录。只有中心思想、没有论证与实施条件，不算完整保留。

此档默认目标：全书完整覆盖至少 90%，每个有效原作章节至少 80%，核心观点与改变结论的条件/限制 100%，有效来源段落去向 100%。盘点时将这些核心观点及条件/限制标记为 `critical`。用户明确要求更高时使用更高目标；当前 CLI 使用上述固定阈值，更高目标须另核报告中的实际比例，不能只凭退出码 0。`partial`、`missing` 不计完整覆盖；排除项必须逐项说明理由并人工审阅，不能为提高比例删掉难写内容。

覆盖前先确定分母。来源盘点完成后冻结信息项的 ID、类型、原作章、源段集合、关键性和知识陈述。允许合并重复阐述，但应保留来源并集与合并理由；重复案例包含新的条件、推理或失败机制时不可整体删除。字数比只作诊断，不能替代知识覆盖判断，也不为短而完整的论点填充废话。

冻结后发现分类、定位或遗漏错误，登记 before/after、旧新摘要、理由与审阅者，保留旧快照并重审受影响映射。不得静默改写冻结摘要，或删掉缺项后宣布达标。分母冻结是防止事后挑选，不是要求保留已证实的来源错误。

`inventory_amendments` 是人工审计记录，校验器不验证修订审批或旧快照。逐项 `review_sha256` 绑定知识项及其目标正文，不包含来源文件哈希或段坐标；来源版本或定位改变时，必须撤销受影响签署、重新对源审阅。重新设置基线后的机器通过不能替代纠错批准。

## 2. 先证明读到了什么

1. 对照实际书源核书名、作者、译者、出版信息、ISBN 与版次，检索页年份不代替版权页。记录源文件与转换文本 SHA256。
2. 逐项核对目录与正文；电子书按实际阅读顺序核章、节和文本，不能只信转换器的标题检测。扫描件先定位 OCR 缺失。作者前言、实质附录、脚注与图表不得无声遗漏。
3. 来源结构与网页阅读结构分别编号。原书四章整理成七个阅读部分，不能把后者写成原书七章。
4. 全文以稳定源段 ID 和 Unicode 字符半开区间定位。每段声明有效或排除及理由；有效段至少连到一个冻结知识项。
5. 图片以完整资源路径、扩展名、资产 SHA256、出现位置识别。同编号的 PNG 与 JPEG 可能是两张完全不同的图；同图多次出现仍登记各次位置。

模型可提供盘点候选，不自动决定分母。审阅者需要读对应来源，检查候选的遗漏、重复、主体、条件与因果方向。纯标题、版权、重复图等可以排除，但不能根据短段、文件名或页数自动认定没有知识。

## 3. 图表与体裁

先实际看图，再结合邻近文字解释。记录轴、单位、图例、方向、范围、非比例示意及不确定之处；数值印刷异常据实保留，不能按常识擅改。图意未审时保持 pending，不把占位符当成已解释。完整图册的审阅与单图解释分别签署。

公开表达优先使用独立解释和必要的原创关系图，不默认重刊原书图表或整份问卷。自绘图不能增加原书没有的因果、顺序或测量精度。对表格按行核对，对步骤检查前提与依赖；图里的五层结构不自动意味着只有一条线性的修复顺序。

| 书型 | 深读单位与重组方式 |
|---|---|
| 论说型 | 定义、主张、理由、证据、反例与适用范围组成一个论证单元 |
| 方法型 | 决策与操作依赖，保留触发条件、步骤、资源及失败边界 |
| 管理寓言 | 提取问题、行动、反馈与管理机制；明确虚构性质，不将完整剧情重述当知识覆盖 |
| 商业史 | 时间和外部环境串联选择与后果；后来的事实与作者当时判断分开 |
| 图解型 | 文字与图意共同盘点，关系图与解释一起验收 |
| 书信/讲话合集 | 保留每篇日期和出处，再按议题组织；不抹去前后观点变化 |

一个单元可覆盖多个来源段，一个知识项也可由多个单元共同解释。不要把逐句换词、长篇对话改述或按原顺序近乎重写全书当成高保留。

## 4. 审阅与机器校验分工

正式目录的公共数据契约：

| 文件 | 用途 |
|---|---|
| `source-map.json` | 源哈希、原作章/节/段范围、排除理由、图像资产与图意审阅、冻结摘要 |
| `content-ledger.json` | 独立知识项、关键性、来源、covered/partial/missing/excluded、目标正文 ID、语义审阅 |
| `deepread.json` | 具有稳定 ID 的深读单元、标题、摘要、正文与源段集合 |
| `coverage-report.json` | 各章/类型/关键项覆盖、缺项清单、结构与语义/图像审阅的分别结论 |

源文件与原图留在私有资料区，不随网页投影。哈希、位置和独立解释可以进入审计资料；不要把私有绝对路径或全文元数据插入公开 HTML。

机器核来源位置、哈希、集合、分母是否变化、正文是否存在以及声明比例。**机器不能判断知识是否真的解释完整。** 语义 reviewer 必须实际审阅来源与目标正文，再记录判定、理由及绑定该正文的摘要；正文变更后旧签署失效。模型输出里的自评、HTTP 成功或传输完成都不是语义批准。

除逐项覆盖审阅外，每本至少抽查 10% 单元的人物、关系、时间与因果，高风险数字、否定、适用条件优先。发现错误超过被抽检断言的 5%，扩到该错误类型的全书检查；必须说明抽样分母与实际范围，不能只写“人工看过”。叙事结果与作者的因果解释分开，寓言不能当成对照实验。

运行公开入口：

```sh
python3 "$SKILL/scripts/book_coverage.py" --book-dir "$DATA/<slug>"
```

退出码 0 表示本脚本所检查的数据契约通过；2 表示 `machine_pass=false`；3 表示机器检查通过，但来源/语义审阅或待核图意尚未放行。待核图意造成完整覆盖不足也可能返回 3。上述 10% 抽检记录不由本脚本核验，须另行验收。报告中的 `release_ready` **只涵盖这套数据契约**，不表示页面、外部事实、索引、产品验收或网站发布已经完成。有效章、有效知识分母或正文为空时必须拒绝；改正文保留旧签署、漏图、漏源段也必须能被拒绝。精确字段及哈希算法以 `scripts/book_coverage.py` 与合成反例测试为唯一实现。

## 5. 三层阅读与页面放行

- **速览**：独立撰写的论点标题与摘要，串起来能看懂本书解决什么、如何推理。
- **理解**：现有章节讲书稿，解释整体结构与关键机制。
- **深读**：完整展开的论证、证据、案例机制、方法及边界；内容来自已审知识项。

先组织主题和论证，再决定折叠。不能把一大段正文藏进 details 就声称完成分层。导出单独的标题速览文件供阅读审查。

全局观点、概念、行动与自检卡应显式关联真实深读 ID；避免从“第 N 章”文本猜跳转。点击必须打开目标标签、阅读部分与折叠单元，滚动位置不能被悬浮导航遮住；初始 hash、切换标签后再次点击同一 hash、手机尺寸都需测试。

渲染须沿用正式五板块骨架与完整交互。直接填骨架与基于已验收成品替换数据是不同的输入契约：后者不能误把未填骨架当成成品。所有继承数据槽必须替换或按契约降级，尤其是公式、作者、评价、延伸内容和隐蔽子视图。仅路由合成测试通过不代表真实书页通过。

新增字段须沿用统一 HTML 转义、标点/破折号与公开来源格式规则，不能绕过旧字段已有的格式处理。

高保留页面使用完整入口：

```sh
python3 "$SKILL/scripts/verify_high_retention.py" --book-dir "$DATA/<slug>"
```

它在整本书上执行原 `verify_page.py` 的 HTML、distill、源文与浏览器检查，现场复算知识覆盖，并检查全部有效来源章、阅读部分、深读单元的映射和实际 DOM 正文一致。不能提交删去附记的临时子集来验收。`--skip-interact` 只供排错，报告会标明未检查浏览器；不构成 Step7 完成。批量时显式声明预期名单、逐本运行并检查每本退出码，不以已存在目录推断名单。非高保留书仍沿用原 Step7/批量入口。

**短来源附记的有限长度规则**：真实来源本身不足800个非空白字符的致谢、编辑背景等，可保持信息完整的较短理解层。不能因标题短、字数少或标记成“附录”自动豁免。实质论证、方法、病例与对话附录仍按主内容验收。需要人工完成 `short-apparatus-review.json`：`schema_version: 1`，`input_sha256` 绑定 `book.txt`、`source-map.json`、`content-ledger.json`、`deepread.json`、`config.json`、`distill.json` 六份实际文件，`entries` 逐项记录阅读部分 `no`、`source_chapter_id`、`reviewer`、`decision: approved`、`rationale` 和全部 `knowledge_item_ids`。

该来源章必须为已审的 `effective`、`source_scope=non_primary`；对应 config 的 `source_role` 只能是 `source_apparatus` 或 `editorial_context`。来源与正文都不得为空或只有标点，该章每个知识项须完整 covered，来源和语义审签均有效，理解层与深读仍完整显示在网页。满足这些条件时，入口只接受该阅读部分的精确 G9 下限差异，G14 引文、定位及其他全部错误仍会拒绝。回执不由工具自动签署；哈希只发现审阅之后的变化，不能替代人工判断其是否真为附记。机器报告列出所有采用该规则的部分，不将其伪装成800字。

逐本另核所有单元可达、桌面/手机截图和五板块的真实书籍身份。对新增检测使用被测入口上的失败反例。最后再完成跨书索引、产品适配与发布；三者不能由 coverage 的绿灯替代。
