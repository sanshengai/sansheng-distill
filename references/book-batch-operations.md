# 多书深读的执行与复盘契约

本文件适用于多本书共用模型车道、审阅人员或发布批次时。单书先按 SKILL.md 选路线：普通书用 `reader-edition-books.md`，明确严格深读才用 `high-retention-books.md`；项目的模型凭证、并发上限、网站和仓库发布命令由该项目配置决定。以下是跨批次可复用的检查点，不把某次书单、模型或日程写成全局默认。

## 1. 模型车道：配置与回执相符

书籍实际派发先经过 book-wave-execution.md 的执行契约；普通书 production_only，不为了填满并发槽安排审稿。请求范围与最终提示由同一清单产生，不另维护审核计划。

每波任务启动前记录 `gateway`、实际模型名、推理参数、输出上限、同时请求上限、凭证所属套餐及工具版本。模型/套餐切换前先做一个最小真实任务，检查响应中的模型、网关、用量与错误类型；权限错误不循环重试，也不擅自切到按调用计费的入口。每个 job 保存任务输入哈希和实际响应元数据。已验收的旧回执若完整输入、参数与输出仍符合当前契约，可以复用；切换套餐本身不是重跑理由。旧模型标定只描述当时的样本，不能代替新车道的事实检出率。

并发数是**跨进程、跨会话的同时请求上限**，不是同时开多少本书或多少 Agent。按当前真实占用分配；人审和读图时释放空闲请求槽。跨进程协调需由共享令牌或等效机制执行，不能只凭 `ps` 快照。出现一组持续超时、429、截断或无法解析时先熔断并定位失败 job，不能靠整波重跑试错。

## 2. 来源开工单：先确认底本，再投长波

正文生产前，为每个版本保留来源预检记录（严格档另在知识分母冻结前核验），至少包括：原文件 SHA256 与版次、目录/正文/附录范围、页序与缺页、各章有效段数、扫描页或图片页、OCR 文字覆盖、图表及数字核图、异常短文本节点、排除项及人工裁决。`source_ready` 只表示拿到底本；只有异常逐项裁决、有效范围和段落 ID 锁定后，才可标来源放行。

- PDF 可用 `scripts/audit_book_source.py` 找印刷页码跳跃、近重复页和低文本图像页。低文本但含图像的页返回待审警告，须核原页是图表、扫描正文还是装饰图。
- EPUB 可用 `scripts/audit_epub_source.py` 找图片承载而文字层很少的章节、逐字切碎的文本节点和缺失图片资源。报告绑定原文件 SHA256；异常章（尤其附录）须打开原版审，不以“能抽出正文”推定全书完整。
- 两个预检脚本退出 2 表示**待审异常**，3 表示无法预检；退出 0 只表示未命中已实现的检测，仍需核目录、章尾、附录和实际图表。不要把预警器当成内容签署器。
- 送模型前检查每个任务的有效原文长度和来源边界。超限必须显式失败并按边界分片，不能静默截断后把模型报出的“缺失”当成书里真的没有。

独立图资产与出现位置分开计数。字节相同且含义上下文未变的图意核读结果可按 SHA 复用；每次出现仍绑定其章节、图号和必要邻文。同图用于不同问题、条件或单位时补看该处上下文，不将几千次行内公式出现数当成几千张独立图片重复核读。正文判断不由相同图片哈希自动继承。

## 3. 阶段回执与定点复用

本节的阶段签收范围服从所选档位：reader按授权使用一份最终制作或审阅收据，其余操作阶段保存真实证据与状态，不额外签六套正式回执；严格在制书仍沿实际消费者契约。

阶段回执至少记录书的唯一标识、阶段、输入文件哈希、输出文件哈希、上游回执哈希、任务哈希、实际模型参数、工具版本、签署者和时间。总账只是索引；恢复时以正式回执、当前文件和 Git 状态交叉核对。输出存在、进程返回成功或旧总账标 `done`，都不能替代签署。

只对已选档位实际存在的阶段传播失效；完整读者版不补造严格分母与逐项签署。来源或正文发生修改时，按**完整输入字节与任务提示哈希**逐层传播失效：先比段落 ID/有效性/章节归属与图资产，再判 inventory、归并、忠实度、写作、事实、覆盖和装配各自是否受影响。输入逐字一致且回执合格的 job 保留，只重派变化或失败项；无法证明等价的回执标 `unverified`，不自动继承。一个成功模型调用不能因为阶段 Agent 失联就再派一次；先查落盘输出与真实回执。冻结知识分母后若重建来源映射或再次冻结，必须核库存修订、图意、`target_ids` 和覆盖校验是否仍有效，禁止让 `checked=0` 被当作绿灯。

工具若提供自动失效检查，必须把缺文件、未知路径、哈希不符、参数缺失列成可解释的拒绝项；不能因为检查器解析不了旧回执，就把旧阶段判为可复用。尚无自动检查器时，人工形成等价证明并随阶段回执保存。

可先运行 `python3 "$SKILL/scripts/check_receipt_inputs.py" <阶段回执.json> --book-dir <书目录> --json-out <审阅目录/receipt-input-check.json>`；回执里的符号键或外部文件用 `--map 键=实际路径` 明确指定。退出 0 **只证明这份回执记录的输入文件仍逐字相同**；退出 2 表示路径缺失、歧义或哈希不符，不能自动复用；退出 3 表示回执不可核。即使退出 0，也还须核任务提示、实际模型参数、输出文件和人工签署，不把这个局部检查冒充完整阶段验收。

## 4. 人工审阅包与质量标定

忠实度、事实或覆盖审计的每条建议，应尽量集中展示：原句与建议句、知识项、精确来源段及相邻段、相关图意、变动字符、被删数字/限定条件、模型理由和历史裁决。审阅者逐项选择采纳、驳回、改分母或待查，并写原书依据；打包只减少查找时间，不代替裁决。成组建议可按同一根因导航，但不能把一组的结论无证据应用给所有项。

复盘分开统计：被采纳的实质修复、被采纳的轻量编辑、已有上下文被忽略、来源误读、非问题/措辞偏好和无效定位。采纳率不是事实错误率，报警数不是返工量；定位错误与语义误报可重叠，不把两者相加。若问题清单持续含“忠实/无需修改”或已保留的限定，先修审核方向与输入，再用既有真错和误报对照验证；不直接放宽事实标准，也不默认追加一轮模型复审。保留原失败记录和主控裁决，改提示只用于后续任务；已有合格书不为验证新提示整书重审。

各档均保留实际消费者的机械检查；普通制作不新增内容审阅，已知制作故障定点修复；获授权审阅的报警按范围回源。抽样的对象、比例和扩查条件只按已选流程执行：严格档用 high-retention-books.md，读者档用 reader-edition-books.md 的章节组抽样；仅仍有知识分母的管理类既有流水线采用 efficient-book-distillation.md 的低风险项审校。原书事实接受策略与质量档位分别记录；不因学科标签恢复全书外查。不要叠加三套抽样或追溯改签历史审阅。优化提示、分组大小或推理参数前，锁定一组已确认真错、误报、局部条件遗漏和原图/相邻段反例；同源同输入比较漏检、误删、解析完整性、墙钟、token 和人工裁决量。**真错漏检增加或有效来源被删，不以节省调用量为由推广。**固定样本有选样偏差，不能冒称总体召回率。

## 5. 排期、完成态与发布

按有效段、知识项、深读单元、扫描页、有效图和待人工裁决数估算工作；同一书单里短书与大部头不能各算一个等量单位。每阶段分别记模型等待、失败重试、读源、人审、装配和页面核验的墙钟，滚动预测只基于同类书的实测；不承诺“每天固定完成多少本”。预算按正文字数外推并留余量：第二批六本心理学读本模型用量合计约 579 万 token，比事前估计（300–420 万）高约四成，主要因两本正文各 20 万字以上、写作一律开思考；每本 87 万到 145 万。

计时与状态只维护一份阶段总账，以稳定 job/request ID 去重，同一调用不因被多个审阅记录引用而重复计费；链接实际任务输出、审核裁决和消费者收据；沿用已有项目记录，不另造同义日报或签署文件。每阶段记录输入/输出版本、开始结束、主动工作、等待原因、调用次数、已知用量与缺失用量、复用/返工原因及下一项阻断。机器耗时从实际日志取得；没有人工计时的读源/审阅标“未计时”，不能用剩余墙钟倒算为人工耗时。

并行调用耗时之和、并行波次墙钟、单书端到端历时分别报告；排队、网络/来源访问、构建发布等待单列，不能从交付历时中抹掉。预算接近耗尽时先判断瓶颈：模型输入重复就去重，报警裁决多就定位误报根因，装配卡住就修真实消费者，发布等待就查同一作业。不要用增加 Agent 或再次全书审阅代替诊断。范围和输入未变、已有有效检查证据时复用；新输入或实际失败才触发相应复验。

对外分开报告：来源齐备、候选、内容放行、已提交、已进入主线、本地页面、发布作业成功、线上直链与目录入口实测。最终范围用明确书单机器比对，允许用户改变范围并保留暂停断点；暂停项不算完成，完成内容也不必因为同批另一本待源而改写为未完成。发布节奏由用户的当期决定控制，不能把某批“全部完成后统一上线”的安排固化为 Skill 默认。但用户确实要求“全批做完一起发”时要知道：合入主线不等于没上线——网站发布按主线最新提交幂等发布，另一条线的常规发布会把已合入的半成品一起带上线（第二批心理学读本的前四本就这样先于后两本上线，含一章未补审的稿子）。要保证“一起发”，只能整批在合入前验完，或把未完成的书留在分支里分批合入；合入前逐本确认进主线的都是终稿，并在合回后、发布前用线上页面核对最终版本。

单书仍验连续阅读、论证与独有案例，而非只验知识项覆盖率；跨书同义术语与互相矛盾的观点在综合层核对，不能为去重把单书的限定和证据删掉。网站上线前还需从读者入口逐本核页面、目录链接、移动端与可读性；数据闸门绿灯不等于线上体验已验收。

## 6. 人审背压与最小执行记录

请求并发和待裁决工作量分别控制。项目给定待审上限；达到上限先收口已在制书，不为填满模型槽生成新审计队列。空槽可做已授权且不新增人审债务的来源机械准备或消费者检查。书的负责人贯穿阶段；来源异常书独立保留，不占正常生产槽。

每阶段只有一个机器可读任务清单作为当前状态入口，引用已有模型回执和裁决证据。任务计划中的预期数、实际成功/失败、格式有效/无效、有效报警、已裁/未裁、实质错误和轻量编辑分别计数；由该清单生成阶段摘要、成本与收尾名单，不手工在多份日志重复抄写。不为普通措辞建议创建独立签署文件，不将每个重试再命名为新生产阶段。原始输入、响应和必要签收仍按项目留存。

归档只核成员、大小及内容哈希；若原件保留且消费者输入未变，不再触发内容模型审阅。提交前逐文件比较实际主线，已有相同内容不重交；当前改动只合并本次明确部分。共用模板/同一最终输入已有有效证据就复用，模板或内容变化才触发相应检查，实际消费者或项目要求的检查仍执行。

试点只同时改变一个可解释的生产决策。采用读者版可以作为完整路线替换试点，但不把它与旧严格档的单环节提速合并计算。至少区分新书完整生产、在制旧书收口和扫描来源准备三个队列；分别报耗时与用量，避免用任务数下降代替端到端成果。

只有获授权审阅的读者版使用一份 `reader-review.json`，引用来源预检、真实模型任务及局部裁决；六个操作步骤不各造正式签署，也不补严格B/C/D回执。若只改包装或卡片、正文及有关语义依据未变，可引用旧人审证据形成当前文件绑定的真实新记录；含义变化须实际复核相应内容。原收据不改写。

## 7. 重试和生产前后依赖

请求完成、格式有效、语义已裁、消费者通过、主线完成分别计数。失败usage未留存则标未知；预算与比较不能把它算零。模型推理token若包含在output中不重复相加；最终答案短也可能推理成本高。

格式或来源编号可确定性恢复时先本地适配，保留原失败且不改语义；length失败先缩小该组完整论证范围，成功组不重发。相同失败原因再次出现，停止原样重试，检查分组、输入与输出契约，转有停止点的定点处理。只读观察超时仍先查原进程终态，不再启动新波。

来源修正、交付资产迁移、索引基线和白名单尽量前置；最终候选冻结后再完整验收，避免中途完整检查随后再搬文件。依赖发生变化时以真实任务字节及语义证据判断可复用范围，不只凭整包文件SHA决定是否重派模型。当前机械绑定必须真实更新，已知实质内容变化不能靠哈希桥接放行。
